Creating server B

Instead of creating B from a snapshot, I used a separate Ubuntu server. The original server (server A) is hosted elsewhere and server B is hosted in cPouta, so snapshot was not possible. The two servers are connected to each other via SSH. I installed Nginx and MySQL, copied the Week 2 frontend and a consistent database dump from A, and recreated the required settings. I then made a read-only backend and page for B.

Storage and backups

On A, the websites are stored in /var/www/viikko1, /var/www/viikko2 and /var/www/viikko3. The required /var/www/html directory and the three website directories are included in timestamped backups. B serves this page from /var/www/viikko4.

A cron job on A sends website files to B hourly over SSH. Backups are stored outside the web directory in /home/sitebackup/backups. Each run records success or failure in a log on A.

Replication and access

MySQL continuously replicates the application database from A to B over an encrypted connection. A dedicated replication account is restricted to B's address. B's application uses a separate local database account with SELECT permission only, and B's database is configured as read-only.

The backup account on B owns the private backup directory and archives. A dedicated Linux account runs B's application, and its database credentials are stored outside the web directory. Replication is not a substitute for historical backups: unwanted changes on A can also be replicated to B.

Tests
  • Both counter pages were accessible in a browser.
  • After A's counter increased, B displayed the updated value.
  • Three reloads of B left the counter unchanged at 105.
  • Both MySQL replication threads reported running with no errors.
  • A manually restored test file matched the original SHA-256 checksum.
  • Two scheduled backup runs and the final reboot test were succesful.

The manual installation of everything was abdolutely terrible and getting the permissions up for the database on server B was rather complicated and I had to go through it several times to understand what was going on. In addition to this, I did most of the work and progress directly on server, and set up the git repo only after everything was already basically done, so I'm glad either one of the servers had any outages during this process.
